# Android 웹 검증 앱

웹의 `dist/` 소스를 Capacitor 8.5.3으로 패키징합니다. 주력 방향은 웹+Android로 확정했습니다. 현재 검증 앱은 별도 패키지 `com.twkim.tinylegion.webqa`, 표시 이름 `Tiny Legion Web QA`를 사용하며 운영 앱/계정과 저장을 공유하지 않습니다. 외부 테스트는 기존 Sites 웹을 기준으로 진행합니다. 출시용 패키지·서명·AAB·스토어 준비는 현재 범위에서 제외하고, 서버 제거/로컬 치트 검증도 별도 단계입니다. Unity 이식 브랜치는 보존합니다.

## 빌드와 설치

Node.js 22 이상, JDK 21, Android SDK 플랫폼/빌드 도구 36을 사용합니다. `android/local.properties`의 `sdk.dir`로 SDK 경로를 설정하며 파일은 Git에서 제외합니다. `JAVA_HOME`은 설치된 JDK 21 경로로 지정합니다.

```sh
npm ci
npm run android:build
adb -s 연결된기기ID install -r android/app/build/outputs/apk/debug/app-debug.apk
adb -s 연결된기기ID shell am start -n com.twkim.tinylegion.webqa/.MainActivity
```

`prepare-android-web.mjs`가 웹 소스를 `.sites-local/android-web/`로 복사하며 `dist/server/`와 `dist/.openai/`는 제외합니다. 이 복사본은 생성물이며 직접 편집하지 않습니다. 파일·음악을 APK에 포함하고 원격 URL을 설정하지 않습니다. 검증 APK에는 인터넷 권한도 없습니다. 기존 `main.js`의 로컬 저장 경로를 사용하며 서버 계정 검증을 제거하거나 새 치트 방지기를 구현하지 않았습니다.

기본 가로 방향, 시스템 바를 숨긴 전체화면과 스와이프로 바를 잠시 표시하는 동작을 사용합니다. 웹 준비 완료 후 현재 활성 상태를 먼저 전달하고 Activity의 pause/resume을 `tiny-legion-app-state` 이벤트로 전달하며 `app-visibility.js`가 문서 숨김과 통합해 실제 상태가 바뀔 때만 정산/복귀를 실행합니다. 숨김 중 전투 틱과 매초 정산을 멈추고 복귀 시 실제 경과 시간으로 정산합니다. Android 파일 선택기는 기존 HTML 입력에 연결됩니다. `NativeGamePlugin`은 저장 내보내기를 Android의 문서 생성 창에 연결하며 취소·쓰기 실패와 완료를 구분합니다. 별도 저장소 권한을 요구하지 않습니다. `native-app.js`가 웹 다운로드와 Android 내보내기를 구분합니다. Android 뒤로가기는 모달의 이전 단계/닫기, 방치 결과 닫기를 우선하고 게임 화면에서는 앱을 백그라운드로 보냅니다. 필수 안내는 기존 닫기 제한을 유지합니다. Galaxy S10 5G에서 설정→메뉴→게임 화면 뒤로가기, 게임 화면에서 앱 백그라운드 전환, 다운로드 폴더에 JSON 내보내기와 재화·편성 내용, 저장 창 취소 후 설정 복귀를 확인했습니다. 저장소 쓰기 실패와 파일 선택기 중 프로세스 종료는 미검증입니다.

## 실기기 검증 경계

2026-10-14 Galaxy S10 5G(SM-G977N), Android 12/API 31, WebView 154에서 APK 설치·가로 전체화면·서버 없는 로딩·소환/배속·메뉴/설정·Android 파일 선택기와 저장 가져오기 확인·편성 드래그/적용을 확인했습니다. 첫 신규 전투의 실패/재출정은 확인했으나 처음부터 끝까지의 안내 수용 완료를 주장하지 않습니다. 이후 목록/방치 검사는 QA 앱 저장을 백업하고 가져온 테스트 계정에서 실행했습니다. 테스트 계정의 진행도를 신규 안내 통과 증거로 사용하지 않습니다. 원본 웹 화면을 유지하며 좁은 가로 화면의 전투 시작 글자 줄바꿈을 수정했습니다. Native 상태 연결 후 약 2분간 홈 화면에 머문 뒤 복귀 수익 안내(도토리 +754, 다이아 +0.04)와 확인 후 안내가 다시 뜨지 않음을 확인했습니다. QA 앱 프로세스를 종료하고 재실행해 재화·미션 진행과 적용한 다람쥐→양 편성이 남는 것을 확인했습니다.

사용자는 배경음이 들리며 효과음은 구분하기 어렵다고 보고했습니다. `audio.js`의 재개 전 짧은 효과음 예약을 재개 완료 후로 바꾸고 숨김/음소거 시 늦은 소리를 생략하도록 했습니다. QA 전용 로그에서 정상 실행 상태와 소리 생성 호출을 확인하고 합성음의 음색·음량·길이를 보강했습니다. 이후 사용자가 소리가 맥북에서 나온다고 알려 미러링의 오디오 전달을 껐습니다. 오디오 전달을 끈 뒤 사용자가 배경음을 끄고 휴대폰에서 효과음이 들리는 것을 확인했습니다. 추가 음성 테스트는 사용자가 취소해 포함하지 않았습니다. 배경음과 함께 들을 때의 상대 음량과 기본 효과음 종류 수용은 별도입니다. 장시간/후반 다수 유닛 성능과 발열·소비 전력은 검증하지 않았습니다.

### 미러링과 휴대폰 소리

실기기 청취 때는 `scrcpy --serial 연결된기기ID --no-audio`로 실행합니다. scrcpy의 기본 출력 캡처는 휴대폰 재생을 끄고 컴퓨터로 소리를 전달하므로, 미러링 기본 설정에서의 청취 결과를 휴대폰 스피커 검증으로 사용하지 않습니다.
