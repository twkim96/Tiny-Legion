# Android 웹 검증 앱

웹의 `dist/` 소스를 Capacitor로 패키징합니다. 주력 플랫폼·외부 테스트 기준·Unity 보존·출시 범위와 향후 서버 없는 검증 전환은 [플랫폼 방향](../SPEC/platforms.md)이 관리합니다. 현재 QA 앱의 패키지·표시 이름·의존성 버전은 `capacitor.config.json`, Android 설정과 `package.json`을 기준으로 확인합니다.

## 빌드와 설치

Node.js 22 LTS, JDK 21, Android SDK 플랫폼/빌드 도구 36을 사용합니다. `android/local.properties`의 `sdk.dir`로 SDK 경로를 설정하며 파일은 Git에서 제외합니다. `JAVA_HOME`은 설치된 JDK 21 경로로 지정합니다.

```sh
npm ci
npm run android:build
adb -s 연결된기기ID install -r android/app/build/outputs/apk/debug/app-debug.apk
adb -s 연결된기기ID shell am start -n com.twkim.tinylegion.webqa/.MainActivity
```

`prepare-android-web.mjs`가 웹 소스를 `.sites-local/android-web/`로 복사하며 `dist/server/`와 `dist/.openai/`는 제외합니다. 이 복사본은 생성물이며 직접 편집하지 않습니다. 파일·음악을 APK에 포함하고 원격 URL을 설정하지 않습니다. 검증 APK에는 인터넷 권한도 없습니다. 기존 `main.js`의 로컬 저장 경로를 사용하며 서버 계정 검증을 제거하거나 새 치트 방지기를 구현하지 않았습니다.

## 네이티브 연결

- 기본 가로 방향과 시스템 바를 숨기는 전체화면을 사용하며 스와이프로 바를 잠시 표시할 수 있습니다. `MainActivity`의 pause/resume은 웹 준비 후 현재 상태와 `tiny-legion-app-state` 이벤트를 전달합니다. `app-visibility.js`가 문서 숨김과 통합합니다. 전투/정산 동작은 [전투](../SPEC/battle.md#모드와-시간)를 따릅니다.
- 파일 가져오기는 기존 HTML 입력에 연결됩니다. `NativeGamePlugin`은 내보내기를 Android 문서 생성 창에 연결하며 별도 저장소 권한을 요구하지 않습니다. JSON은 앱 전용 비백업 임시 파일에 두고 Activity/Capacitor 복원 정보에는 파일 식별자만 남깁니다. 선택 완료·취소·실패 뒤 임시 파일을 제거합니다.
- 프로세스 재생성 뒤 내보내기 결과는 소비 후 지우는 네이티브 상태로 전달합니다. `native-app.js`가 웹 준비 전/도중 결과 도착도 확인하고 새 화면에 성공·취소·실패를 구분해 안내합니다. 웹의 다운로드 경로는 유지합니다.
- Android 뒤로가기의 우선순위·필수 안내 닫기 제한은 [화면 사양](../SPEC/interface.md#android-앱-입력과-저장-내보내기)을 따릅니다.

### 파일 선택 중 프로세스 종료 재현

QA 진행도를 먼저 내보내 보존합니다. Android 문서 저장 창이 열린 뒤 QA 앱이 백그라운드임을 확인하고 `adb shell am kill com.twkim.tinylegion.webqa`로 OS 회수에 가까운 종료를 재현합니다. PID가 사라졌는지 확인한 다음 저장 창에서 저장 또는 취소합니다. `force-stop`은 작업을 제거할 수 있어 같은 재생성 검사로 쓰지 않습니다.

2026-10-15 SM-G977N에서 종료 후 재생성 → 저장한 JSON의 재화·미션·편성 보존, 성공 안내, 취소 안내, 임시 스냅샷 정리를 확인했습니다. 내보내기 스냅샷만 임시로 치워 읽기 실패를 주입한 경우에도 실패/재시도 안내와 게임 진행도 보존을 확인했고, 정상 내보내기 재시도에서 성공 안내와 유효한 JSON도 확인했습니다. 이 주입은 저장 공간 부족·외부 문서 제공자의 실제 쓰기 실패를 검증한 결과가 아닙니다. 원래 QA 진행도 저장을 수정·삭제하지 않았습니다.

## 실기기 검증 경계

2026-10-14 Galaxy S10 5G(SM-G977N), Android 12/API 31, WebView 154에서 APK 설치·가로 전체화면·서버 없는 로딩·소환/배속·메뉴/설정·Android 파일 선택기와 저장 가져오기 확인·편성 드래그/적용을 확인했습니다. 첫 신규 전투의 실패/재출정은 확인했으나 처음부터 끝까지의 안내 수용 완료를 주장하지 않습니다. 이후 목록/방치 검사는 QA 앱 저장을 백업하고 가져온 테스트 계정에서 실행했습니다. 테스트 계정의 진행도를 신규 안내 통과 증거로 사용하지 않습니다. 원본 웹 화면을 유지하며 좁은 가로 화면의 전투 시작 글자 줄바꿈을 수정했습니다. Native 상태 연결 후 약 2분간 홈 화면에 머문 뒤 복귀 수익 안내(도토리 +754, 다이아 +0.04)와 확인 후 안내가 다시 뜨지 않음을 확인했습니다. QA 앱 프로세스를 종료하고 재실행해 재화·미션 진행과 적용한 다람쥐→양 편성이 남는 것을 확인했습니다.

배경음과 효과음은 독립 설정을 사용합니다. 효과음은 오디오 재개 완료 후 예약하고 숨김/음소거 시 늦은 소리를 생략합니다. 오디오 전달을 끈 미러링에서 사용자가 배경음을 끄고 휴대폰의 효과음을 확인했습니다. 배경음과 함께 들을 때의 상대 음량·효과음 종류 수용과 장시간 성능은 남습니다. 추가 음성 테스트는 포함하지 않습니다.

### 미러링과 휴대폰 소리

실기기 청취 때는 `scrcpy --serial 연결된기기ID --no-audio`로 실행합니다. scrcpy의 기본 출력 캡처는 휴대폰 재생을 끄고 컴퓨터로 소리를 전달하므로, 미러링 기본 설정에서의 청취 결과를 휴대폰 스피커 검증으로 사용하지 않습니다.

## 신규 안내와 성능 추가 확인

공통 웹 소스의 새 로컬 계정에서 실제 화면 입력으로 0스테이지 승리, 1-1 실패 안내, 다람쥐 무료 확정 모집, 재출정 승리, 첫 방치 기록과 미션 수령, 1-2 실패 뒤 토끼 무료 확정 모집과 26.6초 재도전 승리를 확인했습니다. 이후 토끼 포함 방치의 38.8초 실패 → 순서 해금 → 교체/비우기/적용으로 토끼 제거 → 40초 방치 생존 → 레벨업 안내 → 양 방패 Lv. 2(체력 605/공격력 27) 첫 성장을 확인했습니다. 같은 origin 재접속 후 Lv. 2, 재화, 토끼가 빠진 방치 편성과 생산 기록이 유지됐습니다. 기본 새로고침에서는 로컬 미리보기의 모듈 초기화가 한 번 지연됐고 같은 origin의 새 문서 URL 재접속은 정상 완료했습니다. 이 로컬 브라우저 현상을 Sites 장애로 단정하지 않습니다. 이 결과는 Sites의 D1·로그인 수용이나 휴대폰 손가락 조작을 대체하지 않습니다.

### 80유닛 부하

`scripts/qa/performance-probe.html`은 현재 `engine.js`와 `renderer.js`를 그대로 읽는 수동 측정 페이지입니다. Android QA 빌드의 복사된 `index.html`에 임시로 사용하고 별도 패키지로 실행했습니다. 측정 뒤 게임용 복사본과 Gradle 설정을 복원했습니다. 페이지를 정적 웹 배포 루트에 넣거나 기존 게임 저장을 불러오지 않습니다.

- 시나리오: 2-10 방치, 앞 10종 편성, 레벨 35, 체력·소환 수급 보너스를 높이고 공격을 낮춘 인공 부하로 실제 80유닛 상한에 도달시킵니다. 밸런스와 정상 성장 계정의 승패를 검증하는 시나리오가 아닙니다.
- SM-G977N / Android 12 / WebView 154.0.8037.106, 전장 828.95×411.43 CSS px, Canvas DPR 2, 30Hz 계산, 화면 미러링을 켠 상태입니다. 전체 게임 HUD·서버 요청은 포함하지 않습니다.
- 30.008초에 1,733프레임(평균 57.8fps), 계산 틱 890회, 최대 80유닛·19투사체를 관찰했습니다. 프레임 간격 P95 16.8ms, 렌더링 CPU 시간 P95 7.6ms, 계산/이벤트 처리 P95 2.2ms이며 33.4ms를 넘는 프레임은 29회였습니다.
- 렌더링 CPU 시간은 GPU 완료 시간을 뜻하지 않습니다. 다른 기기·브라우저, 전체 HUD, 모든 효과 조합과 장시간 발열·배터리 수용은 남습니다. 이 단기 결과만으로 항상 60fps라고 판단하지 않습니다.
