# 미완료 작업

현재 구현은 [SPEC](SPEC.md), 확정 확장 계약은 [확장 설계](SPEC/expansion.md)를 따릅니다. 아래는 기존 개발 목록과 v0.3 기획에서 남은 구현·결정·수용 검증입니다. 문서 초기화가 제품 구현·배포 승인을 대신하지 않습니다.

## 우선 수용 검증

- 어두운 그라데이션 위 그림자·외곽선 없는 재화·스테이지 글자, 기존 상단 메뉴 아이콘과 중앙 정렬한 흰색 사각 소환 카드를 PC와 667×375·844×390·932×430 브라우저에서 확인합니다. 메뉴창 열기·닫기, 전투 모드 전환과 속공 잠금, 준비/결과 화면의 메뉴 접근, 카드 줄 중심·별도 전투 골드·순서 버튼·대포 사이의 겹침, 초상화·가격·쿨타임·자동 소환 차례 구분, 밝은 맵 위 글자 대비 및 안전 영역이 확인되어야 합니다. 현재 저장된 브라우저 권한 설정이 localhost 접근을 차단하므로 실제 화면 검증은 미완료입니다. 코드 검사와 자동 테스트는 실제 화면 검증을 대신하지 않습니다.
- 공격 준비·타격·복귀, 아군/적군 투사체의 비행·착탄, 피격 경직을 같은 가로 화면 크기에서 확인합니다. 정지/재개·2×·저프레임·재전투 시 모션과 피해 시점이 맞아야 하며, 다수 유닛 전투에서 효과 가독성과 프레임 성능을 확인해야 합니다. 바뀐 타격 시간에 따른 생존·생산·클리어 시간의 밸런스는 실제 플레이로 승인합니다.
- Android 실제 WebView에서 Sites 로그인 연결, 저장·파일 이동, 종료·복귀, 터치·긴 누르기, 소리, 전체 화면, 다수 유닛 성능을 확인합니다. 실제 기기에서 진행도 보존과 플레이 흐름을 재현하고 제한을 기록하면 완료입니다. 게임 서버 로그인은 서버 작업 이후 확인합니다.
- iOS WKWebView에서 같은 항목과 안전 영역을 확인합니다. 실제 기기에서 화면 잘림·저장 유실·입력 오작동 여부를 확인해야 합니다.
- 실제 플레이에서 편성·순서가 방치 생존·수익을 의미 있게 바꾸는지, 30초 실패 반복이 120초 생존보다 유리하지 않은지, 하위 스테이지가 더 나은 생산처가 될 수 있는지 확인합니다. 모드별로 다른 최적 편성·보석이 유효한 플레이 결과를 남깁니다.
- 모집·레벨 비용·다이아 공급·첫날 성장 속도를 조정합니다. 모바일에서 모집→강화→재전투 흐름과 다수 유닛의 역할·동작 가독성을 확인해 초기 밸런스를 승인합니다.
- 3~5배로 올린 소환 비용을 실제 플레이로 확인합니다. 초반 첫 소환 대기, 비싼 동료 차례의 대기와 전선 유지, 높은 레벨에서의 유닛 누적, 도전·속공 클리어 시간을 확인해야 합니다. 자동 전투 수량 비교는 전체 스테이지·편성 밸런스 승인을 대신하지 않습니다.

## 계정과 전투 데이터

- Sites D1 서버 계정 저장·재화 변경·기록 검증·서버 날짜·원자적 일일 보상을 설계하고 구현합니다. 공용 인증·기기 연결을 검증하며 동시 클릭·네트워크 재시도·강제 종료에서도 중복 지급과 진행도 유실이 없어야 합니다. 엔드포인트와 마이그레이션·복구 안내를 구현 이후 문서화합니다.
- 진행 중 전투 저장·복구 여부와 전투 재현 기록 정책을 결정합니다. 종료·복귀·새로고침의 결과, 저장 형식과 밸런스 버전 호환성을 명시하고 선택한 정책으로 검증합니다.
- 방치의 비선형 보상 산식, 120초 기준 정산, 골드·다이아 곡선·소수점·상한, 별도 최고 기록 선택, 오프라인 한도·기록 영구 유지 여부를 최종 승인합니다. 성장·보석·각인·버전 변경의 재검증 범위를 정하고 이전 기록에 무검증 보너스가 합성되지 않게 검증합니다. 현재 한 스테이지 생산·8시간 한도·골드 최고 기록은 초기 정책입니다.
- 속공 날짜 경계·미수령 이월/자동 수령 여부·최고 기록 수령, 시간→점수→보상 곡선과 보상 상한·모집 환산을 최종 승인합니다. 현재 Seoul 자정·미수령 초기화 정책을 결정과 구분하며 날짜를 넘는 전투·수령 직전 경계를 검증합니다. 스테이지 교체·웨이브·시간 제한·스킬 허용도 결정합니다. 기존 개발 목록의 “골드/다이아별 최적 기록”이 방치 기록 선택을 뜻하는지 속공 보상 분기를 뜻하는지도 명확히 합니다.

## 성장과 콘텐츠 확장

- 동료 11종 이상 또는 검증 데이터로 상위 10명 일반 레벨 동기화를 구현·검증합니다. 직접 투자만으로 자동 선정하고 동기화 레벨을 재선정에 넣지 않아야 합니다. 10명 미만·동률·미보유 규칙을 결정하며 현재 5종으로 정책을 축소하지 않습니다.
- 일반 레벨 최종 상한·진화 요구 레벨, 진화 단계·재료·형태 선택, 진화와 독립적인 잠재능력을 결정·구현합니다. 특별강화·잠재능력 재화·상한·수급·초기화, 개별 일반 레벨 초기화·환급·균등 강화 여부도 정하고 도전 진행 기반 해금과 함께 검증합니다. 원본 해금표의 번호는 예시입니다.
- 동일 보석+골드 강화, 슬롯 랜덤 각인, 프리셋, 최대 5슬롯의 단계 개방을 구현합니다. 각인 확률·등급·비용·이전 옵션 보존, 프리셋의 각인 공유/별도 세트·자동 적용·중복 장착, 보석 모집 확률·천장·중복 처리·가격을 결정합니다. 보석 교체 후 슬롯 각인과 검증 방치 기록이 보존되어야 합니다.
- 성 방어병력과 전투 스킬 성장을 구현합니다. 시설·배치 수·사거리·모드 제한과 스킬 수·쿨타임·자원·강화 상한을 정하고 일반 동료·방치 전용 지원·수동 스킬의 역할 경계를 검증합니다. 현재 수동 전투의 기본 대포는 이 작업의 완료가 아닙니다.
- 지역마다 10스테이지를 유지하며 지역·적·공간·웨이브와 전술 역할을 확장합니다. 원본 캐릭터 후보는 확정 명단으로 취급하지 않고 실제 플레이에서 패턴과 대체 편성의 차이를 확인합니다.
- 계정/편성 전투력을 참고 지표로 추가합니다. 공격·체력·주기·사거리·특수 효과의 가중치, 경제 보너스 제외·상한·시너지 반영을 결정하고 승패·방치 수익·속공 기록과 분리해 표시합니다.

브라우저나 자동 테스트의 통과는 실제 휴대폰·WebView 수용 검증을 대체하지 않습니다. 최초 배포의 비공개 운영 방침은 [호스팅 안내](operations/storage-and-hosting.md)에 있습니다.
