# 미완료 작업

현재 구현은 [SPEC](SPEC.md), 확정 확장 계약은 [확장 설계](SPEC/expansion.md)를 따릅니다. 아래는 기존 개발 목록과 v0.3 기획에서 남은 구현·결정·수용 검증입니다. 문서 초기화가 제품 구현·배포 승인을 대신하지 않습니다.

## 웹+Android 테스트 안정화

확정 범위는 [플랫폼 방향](SPEC/platforms.md)을 따릅니다. 아래 수용은 실제 기기·Sites에서 확인할 때 완료합니다.

- 세로 플레이 모드의 전장·HUD·소환 카드·모달 배치를 설계하고 웹/Android에 적용합니다. 현재 회전 안내·전체화면 버튼은 세로 플레이 지원 완료가 아닙니다. 회전 전후 진행도·편성 보존과 작은 세로 화면의 터치/스크롤 수용을 확인하면 완료입니다.
- 신규 안내 전체를 휴대폰의 실제 터치와 Sites 서버 계정에서 수용합니다. 공통 웹의 새 로컬 계정에서 첫 성장·재접속까지 확인한 범위와 실기기 기본 동작은 [Android 검증 안내](development/android.md)에 기록합니다.
- 배경음과 효과음의 상대 음량과 저장 공간 부족·외부 문서 제공자의 실제 쓰기 실패를 기기에서 확인합니다. 실패 안내·재시도와 진행도 보존이 완료 조건입니다. 파일 선택 중 프로세스 재생성과 성공/취소·스냅샷 읽기 실패는 [Android 검증 안내](development/android.md#파일-선택-중-프로세스-종료-재현)의 확인 범위를 따릅니다.
- 80유닛·전체 전장의 30초 Android 인공 부하 측정 이후 전체 HUD·효과 조합, 장시간 성능/발열·소비 전력, 다른 기기·WebView의 수용을 확인합니다.
- 서버 없는 로컬 검증 구조를 설계합니다. 명령/보상 반영 경계, 시간 변경 처리, 저장 손상·조작 감지와 복구 정책을 정하고 웹/Android 공통 회귀를 확인한 뒤 전환합니다. 현재 Sites 서버 제거와 계정 저장 전환은 미완료입니다. 단순 SHA-256 체크섬을 치트 방지 서명으로 간주하지 않습니다.

## 우선 수용 검증

아래는 기능 전체·기기별로 남은 수용 항목입니다. [이미 확인한 공통 웹·Android 범위](development/android.md#실기기-검증-경계)를 다시 미검증으로 취급하지 않으며, 일부 통과를 전체 조합의 승인으로 확대하지 않습니다.

- 1280×522·844×390·667×375 브라우저 미리보기에서 여백 없는 전체 화면 전장·중앙 정사각형 5×2 소환 카드·가로 넘침 방지와 골드/대포 배치를 확인했습니다. 메뉴는 1280×591·844×390·667×375에서 줄어든 폭과 닫기 버튼 표시·닫기를 확인했고, 844×390에서 설정 진입·뒤로가기를 확인했습니다. Galaxy S10 QA 앱의 가로 전체화면 기본 확인과 다른 브라우저/기기 수용을 구분합니다. 브라우저 도구막대 표시/숨김·전체화면 진입/종료·회전·노치 안전 영역에서도 전장은 화면을 채우고 캐릭터·성·아이콘·카드 비율은 유지되어야 합니다.

- Android Chrome·Samsung Internet에서 세로 안내의 전체화면 버튼 → 가로 고정 → 게임 재개, 전체화면 종료 뒤 방향 고정 해제를 실제 기기로 확인합니다. iPhone Safari·iPad Safari·WebView에서는 전체화면/가로 고정 미지원·거절 안내, 수동 회전·회전 잠금 해제, 설정의 전체화면 진입/종료를 확인합니다. 390×844 브라우저 미리보기에서 안내·버튼 배치를 확인했습니다. API 순서·실패 처리 자동 검사는 실제 OS 방향 전환 검증과 구분합니다.

- 양 방패(체력 540)·씨앗 다람쥐(공격력 51)의 범용 기준 성능과 속성 숙련/추가 특화 제거를 동료 상세·도감·모집에서 확인합니다. 1-6·2-2의 변경 배율과 실제 처치 골드가 포함된 서버 편성의 성장/보석 안내 난이도를 플레이로 확인합니다. 처치 골드 없는 엔진 기준에서는 2-2 레벨 35가 막히지만, 계정의 처치 골드가 포함되면 같은 레벨로 통과할 수 있어 고정 실패로 취급하지 않습니다.
- 도감·스테이지 속성 구성/웨이브 설명과 방어막 테두리·재생/방해 표식을 PC·모바일 가로 화면에서 확인합니다. 4속성·후반 증원에 따른 소환 순서 선택이 읽히고 전투 화면이 복잡해지지 않아야 합니다. 다른 기기·전체 효과 조합의 WebView 수용은 남습니다.
- 현재 [특수능력](SPEC/abilities.md)과 별도로 진화·추가 잠재능력·특화 각인의 필요성과 해금/비용을 결정합니다. 구현 시 특성 합성 계약과 기록 스냅샷을 보존하고 특수능력 환급/초기화 정책도 결정합니다.
- 광폭화·돌진·광역 공격·상태이상·장갑·소환 후보의 우선순위·대체 해법을 정하고, 주요 적·보스부터 구현합니다. 현재 방어막·재생·중독 도입은 나머지 기믹 구현 완료가 아닙니다.

## 보석 패시브·완전 특화

- [피해 특성 확장](SPEC/expansion.md#피해-특성-확장-미구현)의 보석 패시브(원본 효과 +10%씩 10단계, 최대 2배)와 매우 단단함·매우 강함·매우 매서움을 구현합니다. 현행 특성·보석 모집/강화와 별도이며 아직 미구현입니다.
- 최종 유효 체력 계산과 기존 속성 숙련의 합성·최종 상한, 완전 특화의 패시브 적용 여부, 해금·비용·배정 대상은 구현 전에 확정합니다. 같은 공통 조건·설명·피해 계산을 사용하며 대상 밖 보너스·반복 적용·기존 기록 소급을 만들지 않습니다.

## 계정과 전투 데이터

- 실제 Sites·모바일/WebView에서 응답 본문 유실·15초 제한 시간·재연결의 동일 ID 처리, 인증 만료/테스트 계정 비활성화의 로그인 안내·후속 요청 중단, 전투 도중 밸런스 배포 후 새로고침·기존 기록 보존을 확인합니다. 자동 클라이언트·SQLite 검사는 실제 D1·기기 네트워크 수용 검증과 구분합니다.
- 온라인 연결/인증 안내와 방치 결과 표시는 별도 모듈로 분리했습니다. `main.js`의 전투 생명주기·나머지 화면 렌더링 책임을 분리할 때 기존 모달/전투 회귀를 유지합니다.
- 운영 DB 백업·복원 절차는 아직 제공하지 않습니다. 서버 검증 경계를 유지하는 관리자 복구 절차와 권한·보관 정책을 설계한 뒤 검증합니다.

- [서버 계정](SPEC/server-account.md)의 실제 Sites 로그인·D1 마이그레이션·단일 활성 세션·게스트 연결·배포 회귀를 확인합니다. 1인 사용을 기준으로 구현했으며 동접 수용량은 측정하지 않았습니다. 이후 요청 빈도·입력 재생 CPU·영수증 보관 기간·게스트 생성 제한·요청 제한을 부하 시험과 함께 정합니다.
- 진행 중 전투 저장·복구 여부와 전투 재현 기록 보관 정책을 결정합니다. 현재 서버는 다른 버전의 진행 전투를 거절하고 새로고침·새 시작을 안내하며 이전 생산 기록은 유지합니다. 종료·복귀·새로고침의 결과, 저장 형식과 밸런스 버전 호환성을 명시하고 선택한 정책으로 검증합니다.
- 이전 스테이지 성 체력 100% 완주와 다음 스테이지 90% 완주의 같은 시간당 수익, 40·60·90초의 기간 비례 총보상과 같은 시간당 생산을 실제 플레이로 승인합니다. 다섯 동료 기준 레벨 비용의 초반 1~2회·후반 14~24회 목표(90초 환산)와 미션 수급을 함께 확인합니다. 산식·기간 비례 보상·기간별 정산·실지출 환급·직전 과수급 버전 기록의 재측정은 자동 회귀와 실제 성장 속도 승인을 구분합니다. 도토리·다이아 소수점·상한, 별도 최고 기록 선택, 오프라인 한도·기록 영구 유지 여부는 최종 승인 대상입니다. 성장·보석·각인·버전 변경의 재검증 범위를 정하고 이전 기록에 무검증 보너스가 합성되지 않게 검증합니다. 현재 한 스테이지 생산·8시간 한도·도토리 최고 기록은 초기 정책입니다.
- 속공 날짜 경계·미수령 이월/자동 수령 여부·최고 기록 수령, 시간→점수→보상 곡선과 보상 상한·모집 환산을 최종 승인합니다. 현재 Seoul 자정·미수령 초기화 정책을 결정과 구분하며 날짜를 넘는 전투·수령 직전 경계를 검증합니다. 스테이지 교체·웨이브·시간 제한·스킬 허용도 결정합니다. 기존 개발 목록의 “골드/다이아별 최적 기록”이 방치 기록 선택을 뜻하는지 속공 보상 분기를 뜻하는지도 명확히 합니다.

## 성장과 콘텐츠 확장

- 추가 강화 콘텐츠·전용 재화를 설계한 후 [기존 맵의 하드모드](SPEC/expansion.md#기존-맵의-하드모드)를 구현합니다. 1단계만으로 다음 스테이지를 열고 2·3단계는 선택 도전으로 유지하며, 단계별 배율·보상·3단계 등급/속성 제한은 설계 때 확정합니다.
- 일반 레벨 최종 상한·진화 요구 레벨, 진화 단계·재료·형태 선택, 진화와 독립적인 잠재능력을 결정·구현합니다. 특별강화·잠재능력 재화·상한·수급·초기화, 균등 강화 여부도 정하고 도전 진행 기반 해금과 함께 검증합니다. 원본 해금표의 번호는 예시입니다.
- 신규 보석 배너·보장 정책은 별도 설계하며 기존 옵션·강화 투자와 방치 기록을 보존합니다. 추가옵션 장착 수 확장은 군단 연구소에서 다룹니다.
- 성 방어병력과 전투 스킬 성장을 구현합니다. 시설·배치 수·사거리·모드 제한과 스킬 수·쿨타임·자원·강화 상한을 정하고 일반 동료·방치 전용 지원·수동 스킬의 역할 경계를 검증합니다. 현재 수동 전투의 기본 대포는 이 작업의 완료가 아닙니다.
- 지역마다 10스테이지를 유지하며 지역·적·공간·웨이브와 전술 역할을 확장합니다. 원본 캐릭터 후보는 확정 명단으로 취급하지 않고 실제 플레이에서 패턴과 대체 편성의 차이를 확인합니다.
- 계정 전투력은 체력·초당 공격력 기반 참고 수치로 표시합니다. 사거리·광역·회복·시너지의 역할 가중치와 상한, 실제 전투 결과와의 관계를 결정·검증합니다. 현재 계정 전투력의 범위는 [성장 사양](SPEC/account.md#전투력)을 따릅니다.

### 군단 연구소

[군단 연구소 확장 사양](SPEC/expansion.md#중반-성장-군단-연구소)을 구현하기 전에 다음을 결정합니다.

- 연구소 해금 시점과 도전/하드모드 진행 조건을 정합니다. 하드모드 1단계만 다음 스테이지를 열고 2·3단계는 선택 도전인 기존 계약을 보존합니다. 하드모드 재화가 어느 단계에서 얼마나 수급되는지도 확정합니다.
- 세 공학 분야의 기술 순서, 기술별 유한한 강화 단계와 다음 기술 해금 조건을 확정합니다. 무작위 선택 없이 같은 계정 진행에서 같은 순서·결과가 나오는지 확인합니다.
- 도토리와 하드모드 관련 재화의 종류·수급·소모량을 정하고, 연구 취소/초기화·환급과 저장 호환 정책을 결정합니다. 다른 재화 사용이나 제안 수치는 확정하지 않습니다.
- 성벽 공학 시설의 종류·배치·사거리·자동 수리/포탑 작동 조건, 군수 공학의 소환 대기시간·시작 골드·수용량·배치 한도 효과, 전술 공학의 대포 넉백·탄종·둔화/빙결·긴급 보급 효과와 각 상한을 정합니다.
- 수동 스킬의 도전·속공 내 사용 조건과 속공 기록 반영, 자동 시설의 방치 산정·기록 스냅샷 반영을 정합니다. 자동 시설은 방치에도 반영되고 수동 스킬은 방치에서 발동하지 않는지 모드별로 확인합니다.
- 보석 연계 연구의 분야·순서를 정하고, 모든 보유 보석 종류의 기본 효과를 기준으로 추가옵션 동시 장착 수를 3개에서 최대 5개로 확장하는지 확인합니다. 별도 보석 슬롯 성장·슬롯 각인은 포함하지 않습니다.
- 수용 시 고정 순서·단계 상한·조건·비용·효과를 저장 후 재접속해도 보존하고, 조건/재화 부족·반복 입력에서 잠금 해제·차감·강화가 중복되거나 부분 적용되지 않는지 검증합니다. 기존 하드모드 1단계의 다음 스테이지 해금과 2·3단계 선택 진행도 유지, 도전·속공의 수동 스킬, 방치의 자동 시설 반영을 각각 확인합니다. 밸런스 수치는 여러 편성의 실제 플레이로 별도 승인합니다.

브라우저나 자동 테스트의 통과는 실제 휴대폰·WebView 수용 검증을 대체하지 않습니다. 최초 배포의 비공개 운영 방침은 [호스팅 안내](operations/storage-and-hosting.md)에 있습니다.
