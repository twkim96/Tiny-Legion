# 서버 계정과 보상

이 페이지는 기존 Sites 웹의 현재 계약입니다. 정적 로컬 웹·Android QA 저장과 장기 로컬 검증 전환 범위는 [플랫폼 방향](platforms.md)을 따릅니다.

## 계정과 접속

- 새 탭에 게임 세션이 없으면 `계정 로그인`과 `게스트로 시작`을 먼저 선택합니다. 같은 탭 새로고침은 기존 게임 세션을 재개합니다. 계정 로그인은 Sites의 ChatGPT 인증을 사용합니다. Google 직접 OAuth는 구현하지 않습니다.
- 메뉴 → 설정에서 `로그인됨 · ChatGPT`와 로그인 계정의 이름·이메일, 또는 `게스트 · 로그인 안 됨`을 표시합니다. 이름·이메일은 Sites 인증 헤더에서 읽어 응답하며 계정 인증 키로 사용하지 않습니다. 게스트의 `계정 로그인`은 로그인 계정의 기존 진행도를 열며 게스트와 합치지 않습니다. `계정 연결`은 현재 서버 게스트의 진행도를 귀속합니다. 이미 계정이 있으면 선택창에서 기존 계정으로 이동합니다.
- 로그인은 `/signin-with-chatgpt`로 최상위 페이지를 이동하고, 같은 origin의 `/?login=account` 또는 `/?login=link`로 돌아옵니다. 돌아온 화면에서 요청한 접속/연결을 수행하며 로그인 표시값은 인증에 사용하지 않습니다. Worker가 전달하는 로그인 여부는 버튼 동작 선택에만 사용하고 API는 Sites의 인증 헤더를 계속 확인합니다.
- Sites 배포는 Worker와 D1 `DB`를 사용합니다. 브라우저의 재화·동료·성장·진행도 저장값을 서버로 올리는 경로는 없습니다. 기존 로컬 테스트 저장은 기기에 그대로 남으며 서버 계정으로 이주하지 않습니다.
- 로그인하지 않아도 서버 게스트 계정을 생성합니다. 계정 ID와 비밀 자격 증명은 서버가 생성합니다. 게스트 자격 증명은 `Secure`·`HttpOnly`·`SameSite=Lax` 쿠키에 보관하고 DB에는 SHA-256 해시만 저장합니다. 공개 ID만으로 기록을 변경할 수 없습니다.
- 게스트도 뽑기·비용·보상·전투 검증을 동일하게 받습니다. 쿠키가 없어진 게스트의 기록을 브라우저 저장으로 복구하거나 다른 기기로 옮기지 않습니다. 설정에서 계정 연결을 완료하면 다른 기기에서 이어갈 수 있습니다.
- 계정 연결은 Sites가 제공하는 `oai-authenticated-user-id`와 현재 유효한 게스트 세션을 함께 확인합니다. 서버의 게스트 기록을 그대로 귀속하며 클라이언트 기록은 받지 않습니다. 이미 연결된 계정이 있으면 합산하지 않고 기존 계정으로 접속할 수 있습니다.
- 활성 기준은 마지막 `session/start`가 성공한 게임 세션입니다. 토큰을 재발급하며 이전 토큰의 모든 게임 요청은 `session_replaced`로 거절합니다. 이전 화면은 다음 서버 요청에서 접속 종료를 표시하고 진행을 멈춥니다. Sites 로그인 자체를 다른 기기에서 원격 로그아웃시키는 기능과는 구분합니다.
- 같은 탭의 새로고침은 `sessionStorage` 토큰으로 재개합니다. 다른 기기·새 세션은 이전 진행 전투를 버리고 저장된 계정에서 시작합니다. 토큰이 교체된 화면은 자동으로 접속을 되찾지 않고 사용자가 `여기서 계속하기`를 선택해야 합니다.

## 검증과 저장

- 재화·모집·확정 지급·미션·일일 보상·성장·특수능력·보석·프리셋·계정 초기화는 명령 API를 통해 서버에서 변경합니다. 보유 여부·해금·비용·횟수는 공통 게임 규칙으로 확인합니다. 뽑기 난수는 서버의 암호학적 난수로 생성합니다.
- 방치 생산과 일일 날짜는 서버 시간으로 계산합니다. 기존 최고 생산 기록과 12시간 상한을 사용하며 브라우저 시간이나 요청에 포함한 지급액을 신뢰하지 않습니다. 화면은 서버 정산 사이에 수익을 표시할 수 있지만 저장 잔액은 서버 응답으로 교체합니다.
- 보석 기본 효과는 종류별 가장 높은 보유 단계, 추가옵션은 최대 3개 장착에서 계산합니다. `gem.equip`은 선택 교체를 원자적으로 처리하고 `gem.reroll`은 서버 난수·비용 검증·중복 요청 결과 보존을 사용합니다. 전승 명령은 제공하지 않습니다.
- 전투 시작 시 서버가 편성·능력치·보석·진행 단계의 스냅샷과 전투 ID를 저장합니다. 완료 요청의 승패·재화는 받지 않고, 30Hz 입력 기록으로 공통 엔진을 다시 재생해 결과를 산출합니다. 불가능한 소환·대포·입력 순서·너무 빠른 완료는 거절합니다. 방치는 자동 소환을 재생합니다.
- 전투 스냅샷의 `balanceVersion`이 현재 서버와 다르거나 없으면 완료를 `409 battle_version_mismatch`로 거절하고 보상·진행도·생산 기록을 변경하지 않습니다. 화면은 새로고침을 안내하며 새 전투 시작이 이전 전투를 대체합니다. 서버 시작 응답과 브라우저 엔진 버전이 달라도 시뮬레이션을 시작하지 않고 새로고침을 안내합니다. 이전 최고 생산 기록은 유지합니다.
- 최대 1개 진행 전투를 계정에 보관합니다. 새로운 시작은 이전 전투를 대체합니다. 전투 보상은 시작 스냅샷을 사용하며 중간 성장 변경은 현재 전투를 바꾸지 않습니다. 일반 레벨 환급이 실제 발생하면 환급·기록 초기화와 진행 전투 제거를 같은 트랜잭션으로 저장합니다. 이후 이전 전투의 완료 요청은 `battle_not_found`로 거절합니다. 환급액 0인 요청은 전투를 유지하고, 완료된 환급의 같은 요청 ID 재전송은 영수증 결과만 반환하므로 이후 새로 시작한 전투를 제거하지 않습니다.
- `mission.claim`은 대상 미션의 동료 우편을 계정과 함께 저장하고, `mail.claim`은 수령 여부·소유권/중복 징표를 원자적으로 저장합니다. 받은 우편은 새 요청 ID로 다시 받을 수 없고 동일 요청 ID 재전송은 원래 결과를 반환합니다.
- 명령은 요청 ID를 사용합니다. 같은 ID와 같은 내용의 재시도는 원래 결과를 반환하며 비용·보상을 다시 적용하지 않습니다. 다른 내용으로 ID를 재사용하면 거절합니다. 계정 버전·세션 해시를 조건으로 한 갱신과 영수증 저장을 D1 트랜잭션으로 함께 처리합니다. 충돌 시 최신 상태에서 재시도합니다.
- 경제 버전이 다른 서버 저장은 첫 정산 직전에 새 방치 금액으로 환산하고 계정·영수증을 함께 저장합니다. 클라이언트의 불러오기 처리를 거치지 않은 서버 계정에도 동일하게 적용합니다. 이미 받은 재화는 차감하지 않습니다.
- `gem.upgrade`는 서버 난수로 패시브 강화 성공을 판정합니다. 유효한 확률 실패도 비용을 소모한 정상 명령으로 저장하고 `{success:false, level}` 결과를 반환합니다. 재료·도토리 부족/잘못된 선택은 차감하지 않으며, 같은 요청 ID를 재전송하면 성공·실패 결과와 영수증을 재사용해 중복 소모하지 않습니다.
- 서버에 연결할 수 없으면 게임을 멈추고 재연결을 제공합니다. 응답 본문 유실·성공 응답의 형식 오류·요청/본문 수신 시간 초과는 처리 결과 미확정으로 구분하며 같은 탭의 원래 요청 ID·내용·대기 순서를 보존합니다. 확정 전 후속 명령과 새 명령을 보내지 않고 재연결 때 같은 ID로 결과를 확인합니다. 오프라인 재화 변경이나 나중에 로컬 저장 합산을 지원하지 않습니다.
- 플레이 중 `401 login_required` 또는 `403 test_login_disabled`는 인증 필요 상태로 전환하고 전투 및 후속 명령 전송을 멈춥니다. 서버가 인증 단계에서 거절한 요청과 아직 보내지 않은 대기 요청은 실패로 종료하며 자동 재실행하지 않습니다. 로그인 계정에는 ChatGPT 로그인, 테스트 세션에는 테스트 로그인을 안내합니다. 재인증 후 필요한 행동을 다시 선택합니다. 로그인 폼의 잘못된 비밀번호와 게스트 연결 과정의 로그인 요청은 이 만료 처리와 구분합니다.
- 전투 입력 재생은 결과 변조를 차단하지만 자동 플레이를 판별하지 않습니다. 게스트 생성 남용 방지·요청 제한·동접 부하 시험은 별도 운영 작업입니다.

## 테스트 로그인과 관리자 기능

- `TEST_LOGIN_ENABLED=true`와 유효한 `TEST_LOGIN_ACCOUNTS`가 있을 때 첫 화면·설정에 `테스트 로그인`을 표시합니다. 등록된 아이디/비밀번호로 별도 테스트 계정에 접속합니다. 테스트 계정 생성은 설정된 아이디의 첫 성공 로그인에서만 수행하며 브라우저에서 가입하거나 관리자 역할을 지정할 수 없습니다.
- 비밀번호는 서버 런타임의 비밀 설정에 PBKDF2-SHA256 해시·개별 salt·100,000회 반복값으로 등록합니다. 원문 비밀번호·권한은 게임 저장이나 클라이언트 번들에 넣지 않습니다. 로그인 실패는 폼 안에 표시하며 비밀번호 입력값을 지웁니다. Worker별 로그인 시도 창은 동일 IP/아이디에 1분 5회로 제한하며 공용 서비스의 전역 방어를 대신하지 않습니다.
- 테스트 계정은 `test-login:`으로 구분한 소유자 키와 서버가 생성한 비밀 게임 세션을 사용합니다. 게임 명령은 현재 세션 토큰과 현재 테스트 계정 설정을 확인합니다. 새 로그인은 이전 세션을 무효화하고 테스트 종료·설정 삭제·비밀번호 해시 변경은 기존 테스트 세션도 차단합니다.
- 테스트 관리자 역할은 서버 설정에서만 부여합니다. `root` 관리자 로그인 후 메뉴 → `관리자 기능`에 도토리·다이아 잔액과 각각 `+1,000`·`+10,000` 버튼을 표시합니다. 초반 안내·수동 전투에서도 접근할 수 있습니다. 버튼은 횟수 제한 없이 사용하며 서버 저장에 반영합니다. 한 요청의 재시도는 한 번만 지급하고 새 요청 ID로 다시 누르면 추가 지급합니다.
- `admin.grant`는 현재 관리자 자신의 테스트 계정에만 지급합니다. 일반 ChatGPT 계정·게스트·일반 테스트 계정은 거절하고 임의 재화·금액도 거절합니다. 테스트 계정의 진행도와 지급 재화는 일반 계정으로 연결·합산하지 않습니다. 일반 모집·전투·보상 검증은 테스트 계정에서도 유지합니다.
- 제거 경계는 `server/test-access.js`, `dist/src/test-access-ui.js`와 API·메뉴·로그인 연결부입니다. 스위치만 꺼도 관리자 지급과 테스트 세션을 닫을 수 있으며 기존 게스트/ChatGPT 계정 사양은 유지됩니다.

## API와 구현

| POST 경로 | 기능 |
|---|---|
| `/api/game/session/start` | 계정/게스트 생성·접속 및 이전 세션 교체; 선택값 `identity: guest/account` |
| `/api/game/session/resume` | 유효 세션 재개·복귀 수익 정산 |
| `/api/game/account/link` | 서버 게스트 기록을 Sites 로그인 계정에 연결 |
| `/api/game/test/login` | 활성 테스트 계정의 아이디/비밀번호 확인 및 단일 게임 세션 발급 |
| `/api/game/command` | `{requestId, type, args}` 명령 처리 |

응답은 `account`, `revision`, `serverNow`, `identity`를 포함합니다. 게임 세션은 `X-Game-Session` 헤더로 전달합니다. API는 JSON 요청·동일 origin을 확인하며 모든 응답을 `no-store`로 제공합니다. Sites 인증 헤더는 배포 앞단이 검증한 값만 사용합니다. 로컬 Node 테스트에서 보내는 인증 헤더는 테스트 대역이며 공개 서버 인증으로 쓰지 않습니다.

- `server/api.js`: 인증·게스트·세션·D1 조건부 저장·영수증.
- `server/test-access.js`: 테스트 계정 설정·비밀번호 검증·관리자 권한·지급 허용값.
- `server/commands.js`: 허용 명령과 공통 게임 함수 연결.
- `server/battle.js`: 시작 권한·입력 재생·시간 검증·서버 보상.
- `db/schema.ts`, `drizzle/`: 계정과 요청 영수증 스키마. 스키마 마이그레이션은 런타임에 실행하지 않습니다.
- `dist/src/account-client.js`: 직렬 요청·제한 시간·동일 ID 재시도·인증 만료·접속 교체. `dist/src/cloud-session-ui.js`는 연결/인증 안내와 일시 정지, `dist/src/main.js`는 게임 연결을 담당합니다.
- `tests/account-client.test.js`: 확정된 409 명령 오류의 원래 코드 전달·비재시도·후속 명령 진행과 결과 미확정 네트워크 오류의 동일 ID 재시도를 구분합니다.
- `tests/server-account.test.js`: 실제 SQLite 트랜잭션을 이용한 게스트·연결·변조·세션 교체·동시 재시도·뽑기·수익·전투 검증. Cloudflare D1 및 실제 로그인 수용 검증은 별도입니다.
