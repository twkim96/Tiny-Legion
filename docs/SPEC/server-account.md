# 서버 계정과 보상

## 계정과 접속

- Sites 배포는 Worker와 D1 `DB`를 사용합니다. 브라우저의 재화·동료·성장·진행도 저장값을 서버로 올리는 경로는 없습니다. 기존 로컬 테스트 저장은 기기에 그대로 남으며 서버 계정으로 이주하지 않습니다.
- 로그인하지 않아도 서버 게스트 계정을 생성합니다. 계정 ID와 비밀 자격 증명은 서버가 생성합니다. 게스트 자격 증명은 `Secure`·`HttpOnly`·`SameSite=Lax` 쿠키에 보관하고 DB에는 SHA-256 해시만 저장합니다. 공개 ID만으로 기록을 변경할 수 없습니다.
- 게스트도 뽑기·비용·보상·전투 검증을 동일하게 받습니다. 쿠키가 없어진 게스트의 기록을 브라우저 저장으로 복구하거나 다른 기기로 옮기지 않습니다. 설정에서 계정 연결을 완료하면 다른 기기에서 이어갈 수 있습니다.
- 계정 연결은 Sites가 제공하는 `oai-authenticated-user-id`와 현재 유효한 게스트 세션을 함께 확인합니다. 서버의 게스트 기록을 그대로 귀속하며 클라이언트 기록은 받지 않습니다. 이미 연결된 계정이 있으면 합산하지 않고 기존 계정으로 접속할 수 있습니다.
- 활성 기준은 마지막 `session/start`가 성공한 게임 세션입니다. 토큰을 재발급하며 이전 토큰의 모든 게임 요청은 `session_replaced`로 거절합니다. 이전 화면은 다음 서버 요청에서 접속 종료를 표시하고 진행을 멈춥니다. Sites 로그인 자체를 다른 기기에서 원격 로그아웃시키는 기능과는 구분합니다.
- 같은 탭의 새로고침은 `sessionStorage` 토큰으로 재개합니다. 다른 기기·새 세션은 이전 진행 전투를 버리고 저장된 계정에서 시작합니다. 토큰이 교체된 화면은 자동으로 접속을 되찾지 않고 사용자가 `여기서 계속하기`를 선택해야 합니다.

## 검증과 저장

- 재화·모집·확정 지급·미션·일일 보상·성장·특수능력·보석·프리셋·계정 초기화는 명령 API를 통해 서버에서 변경합니다. 보유 여부·해금·비용·횟수는 공통 게임 규칙으로 확인합니다. 뽑기 난수는 서버의 암호학적 난수로 생성합니다.
- 방치 생산과 일일 날짜는 서버 시간으로 계산합니다. 기존 최고 생산 기록과 8시간 상한을 사용하며 브라우저 시간이나 요청에 포함한 지급액을 신뢰하지 않습니다. 화면은 서버 정산 사이에 수익을 표시할 수 있지만 저장 잔액은 서버 응답으로 교체합니다.
- 전투 시작 시 서버가 편성·능력치·보석·진행 단계의 스냅샷과 전투 ID를 저장합니다. 완료 요청의 승패·재화는 받지 않고, 30Hz 입력 기록으로 공통 엔진을 다시 재생해 결과를 산출합니다. 불가능한 소환·대포·입력 순서·너무 빠른 완료는 거절합니다. 방치는 자동 소환을 재생합니다.
- 최대 1개 진행 전투를 계정에 보관합니다. 새로운 시작은 이전 전투를 대체합니다. 전투 보상은 시작 스냅샷을 사용하며 중간 성장 변경은 현재 전투를 바꾸지 않습니다.
- 명령은 요청 ID를 사용합니다. 같은 ID와 같은 내용의 재시도는 원래 결과를 반환하며 비용·보상을 다시 적용하지 않습니다. 다른 내용으로 ID를 재사용하면 거절합니다. 계정 버전·세션 해시를 조건으로 한 갱신과 영수증 저장을 D1 트랜잭션으로 함께 처리합니다. 충돌 시 최신 상태에서 재시도합니다.
- 서버에 연결할 수 없으면 게임을 멈추고 재연결을 제공합니다. 오프라인 재화 변경이나 나중에 로컬 저장 합산을 지원하지 않습니다.
- 전투 입력 재생은 결과 변조를 차단하지만 자동 플레이를 판별하지 않습니다. 게스트 생성 남용 방지·요청 제한·동접 부하 시험은 별도 운영 작업입니다.

## API와 구현

| POST 경로 | 기능 |
|---|---|
| `/api/game/session/start` | 계정/게스트 생성·접속 및 이전 세션 교체; 선택값 `identity: guest/account` |
| `/api/game/session/resume` | 유효 세션 재개·복귀 수익 정산 |
| `/api/game/account/link` | 서버 게스트 기록을 Sites 로그인 계정에 연결 |
| `/api/game/command` | `{requestId, type, args}` 명령 처리 |

응답은 `account`, `revision`, `serverNow`, `identity`를 포함합니다. 게임 세션은 `X-Game-Session` 헤더로 전달합니다. API는 JSON 요청·동일 origin을 확인하며 모든 응답을 `no-store`로 제공합니다. Sites 인증 헤더는 배포 앞단이 검증한 값만 사용합니다. 로컬 Node 테스트에서 보내는 인증 헤더는 테스트 대역이며 공개 서버 인증으로 쓰지 않습니다.

- `server/api.js`: 인증·게스트·세션·D1 조건부 저장·영수증.
- `server/commands.js`: 허용 명령과 공통 게임 함수 연결.
- `server/battle.js`: 시작 권한·입력 재생·시간 검증·서버 보상.
- `db/schema.ts`, `drizzle/`: 계정과 요청 영수증 스키마. 스키마 마이그레이션은 런타임에 실행하지 않습니다.
- `dist/src/account-client.js`, `dist/src/main.js`: 직렬 요청·네트워크 재시도·접속 교체와 UI 연결.
- `tests/server-account.test.js`: 실제 SQLite 트랜잭션을 이용한 게스트·연결·변조·세션 교체·동시 재시도·뽑기·수익·전투 검증. Cloudflare D1 및 실제 로그인 수용 검증은 별도입니다.
