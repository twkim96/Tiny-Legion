# 성장과 계정 저장

## 현재 성장·경제

아래 수치는 초기 검증용입니다. 원본 기획의 예시를 최종 확정한 값으로 취급하지 않습니다. 조정값의 근거는 `dist/src/account.js`, 전투 적용은 `dist/src/engine.js`입니다.

- 시작 골드 600, 다이아 60, 기본 동료 5종입니다. 계정 재화는 소환에 사용하는 전투 골드와 구분합니다.
- 일반 레벨은 골드로 올리며 비용은 증가합니다. 현재 상한은 100, 공격·체력은 전투 적용 레벨에 따라 선형 증가합니다.
- 동료 모집은 다이아 30을 사용해 5종 중 한 동료 조각을 줍니다. 특별강화는 같은 동료 조각 3개로 1단계, 현재 상한 20입니다. 특별강화는 일반 레벨과 별도 저장하고 전투 적용 레벨에 합산합니다.
- 일반 레벨 전체 초기화는 무료이며 투자 골드를 전액 환급합니다. 특별강화·조각·해금 진행은 보존하고 생산 기록은 무효화합니다. 초기화 전 누적 생산은 먼저 정산합니다.
- 도전 진행도에 따라 다음 스테이지를 엽니다. 각 스테이지의 첫 완료만 골드·다이아를 지급합니다.
- 현재 동료 모집·특별강화는 시작부터 사용 가능하고, 1-3 완료 뒤 속공·보석을 엽니다. 원본 기획의 진행도 기반 성장 해금 확대와 상위 10명 동기화는 [확장 설계](expansion.md)의 미구현 방향입니다.

## 보석

- 현재 1슬롯, 공격 +10%의 용기, 체력 +15%의 온기, 새 방치 골드 기록 +15%의 풍요 3종입니다.
- 보석 조각 5개 또는 다이아 30으로 동일한 모집 목록을 사용합니다. 첫 보석은 자동 장착하며 이후 자유 장착·해제·교체합니다.
- 장착 변경은 다음 전투에 반영합니다. 이전 방치 기록의 수익은 [기록 보존 규칙](battle.md)에 따라 그대로 유지합니다.
- 동일 보석 강화·슬롯 각인·프리셋·최대 5슬롯은 현재 구현하지 않았습니다. 보석과 각인의 독립성은 [확장 설계](expansion.md)를 따릅니다.

## 저장 경계

- `localStorage`의 `tiny-legion.save.v1`에 버전 1 계정을 JSON으로 저장합니다. 재화, 일반 레벨·조각·특별강화, 소환 순서, 도전 해금·첫 보상 상태, 방치 기록·생산 스테이지·정산 시각, 보석과 일일 속공 상태, 소리·속도 설정을 포함합니다.
- 진행 중인 전투 상태는 저장하지 않습니다. 전투 복구·재현 정책은 [TODO](../TODO.md)에 있습니다.
- 불러올 때 `normalizeAccount`가 알려진 동료·장비, 수치 범위, 일일 키를 정규화합니다. 손상 JSON을 읽지 못하면 새 계정과 경고를 반환합니다. 버전이 맞지 않는 저장도 새 계정으로 처리합니다.
- 저장 실패 시 UI는 경고와 파일 내보내기를 안내합니다. 정규화는 보상 진위 검증이나 조작 방지가 아닙니다.
- Sites 접근 로그인과 게임 계정은 별개입니다. 서버 저장·보상 검증·기기 간 자동 동기화는 없으며 기기 시간·저장 파일 조작을 방어하지 않습니다. 실제 결제·경쟁 순위의 신뢰할 수 있는 계정으로 사용하지 않습니다.
- 사용자 백업·불러오기·원본 보존 방법은 [저장과 복구](../operations/storage-and-hosting.md)에 있습니다.

## 코드와 기존 검증

- `dist/src/account.js`: `newAccount`, `normalizeAccount`, `growUnit`, `enhanceUnit`, `refundLevels`, `completeChallenge`, `recruitUnit`, `recruitGem`, `loadAccount`, `saveAccount`.
- `dist/src/main.js`: `persist`, `renderGrowth`, `renderRecruit`, `renderSettings`.
- `tests/account.test.js`: 환급·기록 무효화, 첫 보상 중복 방지, 보석 모집, 손상 입력·짧은 순서 정규화. 파일 다이얼로그·저장 불가 안내·실기기 수명주기 검증은 자동 테스트와 별도입니다.
