# 저장·복구와 호스팅

## 기기 내 진행도 보존

Sites 배포의 진행도는 서버 D1에 저장하며 [서버 계정과 보상](../SPEC/server-account.md)을 따릅니다. 로컬 저장 가져오기는 제공하지 않습니다. 게스트는 쿠키를 보존해야 같은 계정으로 돌아올 수 있습니다. 다른 기기에서 이어가려면 설정에서 계정을 연결합니다. 서버 초기화는 현재 게임 계정만 새 시작 상태로 바꾸며 복구용 파일 업로드는 허용하지 않습니다.

아래 파일 저장·복구 안내는 `npm run dev` 정적 로컬 모드에만 적용됩니다.

- 저장 위치·형식과 실패 동작은 [계정 저장](../SPEC/account.md)의 계약을 따릅니다. 브라우저 저장은 사이트 origin에 속하므로 localhost와 배포 주소가 자동 공유하지 않습니다.
- 메뉴 → 설정 → 저장 파일 → 내려받기로 `tiny-legion-save.json`을 내보냅니다. 브라우저 데이터 삭제·주소 변경·기기 이동 전에 보관합니다.
- 대상 브라우저에서 설정 → 불러오기를 선택합니다. 버전 1 JSON과 필수 필드를 검사하며 1,000,000바이트를 넘는 파일은 거절합니다. 확인 창에서 적용하면 현재 진행도를 교체합니다. 첫 안내 중 저장은 해당 안내 단계로 복귀하며, 안내를 마친 저장은 방치 전투를 새로 시작합니다.
- 불러오기 전에 현재 진행도도 별도 파일로 보관합니다. 복구는 보관한 파일을 다시 불러오는 방식이며 자동 병합·서버 복구는 없습니다.
- 첫 플레이를 다시 시험하려면 메뉴 → 설정 → 계정 초기화 → 초기화하고 시작을 사용합니다. 확인창의 취소는 진행도를 유지합니다. 초기화 전에 저장 파일을 내려받으면 나중에 불러오기로 복구할 수 있습니다. 양 방패만 가진 0스테이지로 복귀하며 초기화 시 실제 브라우저 데이터 전체를 삭제하지 않습니다.
- 저장 접근이 실패하면 내보내기를 사용합니다. 손상 저장을 읽지 못한 뒤의 새 계정은 기존 진행도 복구를 뜻하지 않습니다.

## 호스팅

- `.openai/hosting.json`은 기존 프로젝트 ID와 D1 `DB`를 선언하며 `static`을 사용하지 않습니다. `npm run build`는 유지하는 `dist/` 소스를 읽어 `dist/server/index.js` Worker에 화면 파일을 포함하고 `dist/.openai/`에 배포 설정·스키마 마이그레이션을 복사합니다. 이 두 경로만 생성물이며 `dist/src/` 등 게임 소스를 지우지 않습니다.
- 기존 운영 방침은 기획 검증용 Sites 비공개 배포입니다. Sites source helper를 통한 Git 동기화·아카이브 경로를 사용합니다. 현재 저장소에는 별도 배포 스크립트가 없습니다.
- 비공개 접근 로그인은 게임 서버 계정 저장과 별개입니다. 실제 접근·배포 상태는 배포 시 Sites에서 확인해야 하며 문서 초기화로 확인한 상태가 아닙니다.
- D1 스키마는 `db/schema.ts`와 `drizzle/`가 관리합니다. `npm run db:generate`로 새 SQL을 생성하고 이후 적용된 SQL·스냅샷·저널을 수정하지 않습니다. Sites가 배포 중 마이그레이션을 적용합니다. 클라이언트 파일 불러오기를 서버 복구 수단으로 사용하지 않습니다. 운영 DB 백업·관리자 복구 절차는 추후 결정합니다.
- 현재 Sites 접근 정책을 유지합니다. 비공개 사이트 앞단은 익명 방문을 허용하지 않을 수 있으므로 서버 게스트 기능과 익명 공개 접근은 별개입니다. 공개 전환은 별도 요청으로 진행합니다.
- `dist/style.css`는 Google Fonts의 DM Sans·Noto Sans KR을 불러옵니다. CSS의 대체 글꼴을 사용하므로 네트워크 제한 시 글꼴이 달라질 수 있습니다. 캐릭터 리소스는 직접 관리하는 SVG입니다.

사이트 수정은 로컬 작업·저장만 요청한 경우를 제외하고 기존 접근 설정을 확인해 비공개 배포합니다. Git 커밋과 배포 결과는 구분합니다. 기기별 수용 검증은 [TODO](../TODO.md)에 남깁니다.
